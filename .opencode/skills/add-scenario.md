# Скилл: добавление нового сценария

Используй этот файл каждый раз, когда нужно добавить новый сценарий в КиберЩит.

---

## Шаг 1 — Определи основу сценария

Ответь на вопросы перед написанием кода:

- **Схема мошенничества:** что именно делает злоумышленник? (звонок, сообщение, ссылка, визит)
- **Канал:** телефон / мессенджер / сайт / дверь
- **Крючок:** что заставляет жертву реагировать? (страх, любопытство, жадность, срочность, доверие)
- **Сложность:** `easy` / `medium` / `hard`
  - easy — одна очевидная ловушка, 6 шагов
  - medium — несколько этапов давления, 7–8 шагов
  - hard — цепочка манипуляций, эмоциональное давление, 8–10 шагов

## Шаг 2 — Заполни шаблон

Скопируй и заполни:

```js
{
  id: 'уникальный-id-через-дефис',        // только латиница и дефисы
  title: 'Название карточки',              // до 4 слов
  tagline: '«Цитата мошенника или суть»',  // короткая, в кавычках-ёлочках
  difficulty: 'medium',                    // easy | medium | hard
  icon: '🔗',                              // эмодзи или SVG-иконка
  attacker: {
    name: 'Имя/роль злоумышленника',       // как отображается в шапке чата
    status: 'статус под именем'            // например: 'звонок активен', 'печатает'
  },
  intro: 'Ситуация для пользователя...',   // 2–3 предложения, разговорный язык
  timeLimit: 25,                           // секунд на ход (по умолчанию 25)
  start: 's1',                             // id первого шага
  steps: {

    s1: {
      messages: [
        { text: 'Первое сообщение мошенника.', delay: 400 },
        { text: 'Второе сообщение (если нужно).', delay: 1200 }
      ],
      question: 'Как ответите?',
      options: [
        {
          text: 'Безопасный вариант ответа',
          safe: true,
          feedback: 'Почему это правильно — конкретно и коротко.',
          next: 's2'
        },
        {
          text: 'Опасный вариант ответа',
          safe: false,
          feedback: 'Чем именно опасен этот выбор.',
          next: 'lose'
        }
      ],
      onTimeout: {
        feedback: 'Промедление дало мошеннику преимущество.',
        next: 'lose'
      }
    },

    s2: {
      // ... следующий шаг
    },

    // Последний шаг всегда ведёт к 'win'
    sN: {
      messages: [
        { text: 'Финальная попытка мошенника.', delay: 400 }
      ],
      question: 'Финальное решение?',
      options: [
        {
          text: 'Правильное финальное действие',
          safe: true,
          feedback: 'Вы успешно распознали схему и вышли из ситуации.',
          next: 'win'
        },
        {
          text: 'Неправильное финальное действие',
          safe: false,
          feedback: 'Чем это заканчивается для жертвы.',
          next: 'lose'
        }
      ],
      onTimeout: {
        feedback: 'Нерешительность сыграла против вас.',
        next: 'lose'
      }
    }

  }
}
```

## Шаг 3 — Правила написания текстов

**Мошенник:**
- Говорит коротко — 1–2 предложения за сообщение
- Использует давление: срочность, авторитет, страх, жалость
- Не объясняет лишнего — только то, что нужно для манипуляции
- Может использовать канцелярит («зафиксирована операция») или дружеский тон — зависит от схемы

**Варианты ответа пользователя:**
- Не больше 4 вариантов на шаг, оптимально 2–3
- Формулировка от первого лица: «Не назову», «Позвоню сам», «Открою ссылку»
- Безопасный вариант не всегда очевиден — иногда оба звучат разумно

**Feedback:**
- Объясняет механику, а не оценивает пользователя («Верно: банк не просит...», а не «Молодец!»)
- Для опасного выбора — конкретное последствие, не абстрактное («код даёт доступ к аккаунту», а не «это опасно»)
- Длина: 1–2 предложения максимум

**Стиль:**
- Аудитория — школьники 10–17 лет
- Живой разговорный язык, никакого канцелярита в объяснениях
- Технические термины объяснять в скобках при первом употреблении

## Шаг 4 — Чеклист перед добавлением

Проверь каждый пункт:

- [ ] `id` уникален и не совпадает с существующими сценариями
- [ ] Все `next` ссылаются на существующие ключи шагов или на `'win'`/`'lose'`
- [ ] Каждый путь через сценарий в итоге ведёт к `'win'` или `'lose'`
- [ ] Нет шага без `onTimeout`
- [ ] `start` совпадает с id первого шага в `steps`
- [ ] У каждого шага минимум 2 варианта ответа
- [ ] Хотя бы один вариант на каждом шаге имеет `safe: true`
- [ ] `intro` написан для школьника, понятен без контекста
- [ ] Сценарий добавлен в таблицу в `AGENT.md`

## Шаг 5 — Куда добавить в коде

Открой `js/code.js`, найди массив `scenarioBlueprints` и добавь новый объект **в конец массива** перед закрывающей `]`.

```js
const scenarioBlueprints = [
  { id: 'bank-call', ... },
  { id: 'kufar-buyers', ... },
  // ... существующие сценарии ...
  { id: 'твой-новый-сценарий', ... }  // ← сюда
];
```

## Примеры реальных схем для вдохновения

- Фейковый розыгрыш призов в соцсетях («вы выиграли, введите данные карты»)
- Звонок от «техподдержки» игры («аккаунт взломан, назови пароль»)
- Сообщение от «администратора» школьного чата
- Фишинговая ссылка под видом результатов ЦТ/ЕГЭ
- «Работа» с предоплатой за материалы
- Романтическая переписка с просьбой прислать деньги
- QR-код на объявлении, ведущий на поддельный сайт
