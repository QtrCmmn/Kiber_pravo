## Архитектурные решения

### Анимации
- `wow.js` и `animate.css` **удалены** — заменены нативным `IntersectionObserver`
- Классы `.wow` на элементах HTML сохранены для совместимости, не удалять
- Анимации управляются через CSS-классы: `anim-visible`, `anim-fade-up`, `anim-fade-down`, `anim-fade-left`, `anim-zoom-in`
- `data-wow-delay` продолжает работать (читается в JS как `el.dataset.wowDelay`)

### Тема (светлая / тёмная)
- Хранится в `localStorage` по ключу `'theme'`
- Переключается через атрибут `data-theme` на `<html>`
- Чекбокс `#theme-checkbox` управляет темой

### Бургер-меню
- Элементы: `#burger`, `.header__list`, `#menuOverlay`
- При открытии блокируется скролл (`document.body.style.overflow = 'hidden'`)
- Закрывается при клике на оверлей или пункт меню

### Тренажёр — сценарии
- Данные хранятся в массиве `scenarioBlueprints` в `js/scenarios.js`
- Каждый сценарий содержит шаги (`steps`) с вариантами ответов
- Поля сценария: `id`, `title`, `tagline`, `icon`, `attacker`, `intro`, `timeLimit`, `start`, `steps`
- **3 жизни**: неверный ответ → −1 жизнь, тайм-аут → −1 жизнь, игра заканчивается только при `lives === 0`
- **Опции перемешиваются** при каждом запуске (Fisher-Yates shuffle) — порядок не фиксирован
- **Мини-ветвления**: 1–3 на сценарий, безопасный вариант может вести на `'win'` (досрочная победа)
- **Нет `next: 'lose'`** — все неверные ответы просто отнимают жизнь

#### Структура шага (объектный формат):
```js
{
  messages: [
    { text: 'Текст от мошенника', delay: 600 }
  ],
  question: 'Как ответите?',
  options: [
    {
      text: 'Текст варианта',
      safe: true,           // true = правильный ответ
      feedback: 'Объяснение почему этот выбор верный/неверный',
      next: 'step2'         // id следующего шага, 'win' или 'lose'
    }
  ],
  onTimeout: {
    feedback: 'Что произошло при промедлении'
    // next отсутствует — тайм-аут снимает 1 жизнь и игра продолжается
  }
}
```

## Правила для агента

### Что можно
- Рефакторить модули в `js/` без изменения внешнего поведения
- Добавлять новые сценарии в массив `scenarioBlueprints` — см. `assets/docs/scenarios/GUIDE.md`
- Улучшать CSS-анимации в `style.css`
- Оптимизировать производительность (lazy load, defer, async)

### Что нельзя
- Подключать внешние фреймворки (React, Vue, Angular и т.д.)
- Подключать новые CDN-зависимости без явного запроса автора
- Менять поля `id`, `title` существующих сценариев — они могут использоваться в аналитике
- Удалять классы `.wow` с элементов HTML без замены логики анимаций
- Использовать `var` и jQuery
- Упрощать или формализовать язык текстов — аудитория это школьники, стиль живой

### Стиль кода
- ES6+: `const`/`let`, стрелочные функции, шаблонные строки
- Комментарии на **русском языке**
- `setTimeout` вместо `setInterval` для одноразовых задержек
- `DOMContentLoaded` вместо `window.onload` где возможно
- Все JS-файлы — ES-модули с `export`/`import`, в HTML подключены через `type="module"`

### Стиль текстов сценариев
- Аудитория — школьники 10–17 лет: короткие фразы, никакого канцелярита
- Мошенник говорит убедительно, с давлением, иногда агрессивно
- Правильный ответ в `feedback` объясняет **почему** это безопасно, а не просто хвалит
- Неправильный ответ в `feedback` объясняет **чем именно** опасен этот выбор
- Длина одного сообщения мошенника — 1–2 предложения максимум
- Количество шагов в сценарии — от 6 до 10

## Процесс добавления сценария

При добавлении нового сценария **всегда читай** `assets/docs/scenarios/GUIDE.md`.
Там полный чеклист, шаблон и примеры.

Краткий порядок:
1. Придумать реальную схему мошенничества (или взять из новостей)
2. Заполнить шаблон сценария по инструкции в `assets/docs/scenarios/GUIDE.md`
3. Добавить объект в конец массива `scenarioBlueprints` в `js/scenarios.js`
4. Проверить: каждый путь ведёт к `'win'` или `'lose'`, нет оборванных `next`
